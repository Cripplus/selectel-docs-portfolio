- «Как мы следим за птицами: Android, компьютерное зрение и 10 000 км данных о миграции»

Хабр любит статьи в формате «как мы сделали». Заголовок сразу называет технологии (Android, CV) и обещает конкретику — цифру 10 000 км. Это цепляет и разработчиков, и тех, кто интересуется применением технологий.

Неожиданное сочетание «орнитология + Android» создаёт интригу.  
Заголовок подчёркивает прикладное применение ML и привлекает широкую аудиторию, включая тех, кто интересуется нестандартными ML‑кейсами.

## Задание 2. Работа с правками заказчика

### Условие

Заказчик просит переработать текст‑ретроспективу:

- убрать лирику;
- добавить примеры;
- больше рассказать про технологии.

Ниже — план действий и подход к переработке текста.

---

### План действий

#### 1. Синхронизация с заказчиком

Перед внесением правок уточняю ожидания:

- **Что именно считается «лирикой»?**  
  Где проходит граница между допустимым контекстом и лишней эмоциональностью.

- **Какие технологии нужно упомянуть и с какой глубиной?**  
  Нужны ли названия библиотек, протоколов, алгоритмов, метрик.

- **Есть ли внутренние данные и кейсы, которые можно использовать?**  
  Полевая статистика, метрики качества, производительность, реальные сценарии.

- **Кто целевая аудитория текста?**  
  Инженеры, менеджеры, смешанная аудитория — от этого зависит уровень детализации.

Правки без такого брифинга — работа «вслепую».

---

#### 2. Точечное удаление «лирики»

Я не переписываю текст с нуля, а убираю только те фрагменты, которые не несут фактической нагрузки.

**✗ Было (лирика)**  
> Птицы — символ свободы. Люди всегда мечтали понять их тайные маршруты. Сотни лет учёные смотрели в небо и гадали…

**✓ Стало (конкретика)**  
> До появления радиочастотных меток орнитологи отслеживали миграции по кольцеванию — точность составляла ±200 км.

Сохраняю полезный контекст и переходы, убираю только пустые эмоциональные вставки.

---

#### 3. Добавление технического слоя

Для каждого смыслового блока задаю вопрос:  
**«Как это работает под капотом?»** — и добавляю детали: протокол, алгоритм, стек, формат данных, метрики.

**✗ Было**  
> Система определяет вид птицы по фото.

**✓ Стало**  
> Модель MobileNetV3 (Android NN API) классифицирует 312 видов за 80 мс при точности top‑1 = 91,4%.

Так текст становится технически насыщенным и полезным для инженерной аудитории.

---

#### 4. Добавление конкретных примеров

Абстрактные формулировки заменяю на кейсы с числами и измеримыми результатами:

- «В 2023 году система отследила 4 200 особей зяблика на маршруте Скандинавия → Африка».  
- «Одна сессия записи — 45 минут, размер лога — ~12 МБ, синхронизация по Wi‑Fi каждые 6 часов».  
- «False positive на схожих видах снизился с 14% до 3% после дообучения на региональном датасете».

Такие примеры делают текст убедительным и прикладным.

## Задание 3. Инфраструктурная связка Selectel

### Выбранные продукты Selectel

#### Облачные сети (VPC)

**Продукт:** Cloud Networks / VPC  
**Роль:** приватная сеть

Изолированная виртуальная сеть, которая объединяет все компоненты и обеспечивает приватную маршрутизацию без выхода в интернет.

**Почему выбран**

Selectel VPC позволяет создать изолированные подсети и настроить маршруты между сервером и хранилищами без публичных IP‑адресов.

**Подтверждение в документации**

Документация Selectel: «Облачные сети позволяют объединять серверы в изолированные сети с управляемой маршрутизацией» — cloud.selectel.ru/networks

---

#### Облачный сервер

**Продукт:** Cloud Servers (VDS/VPS  
**Роль:** основной сервер

Виртуальный сервер, на котором разворачивается приложение и бизнес‑логика корпоративной системы.

**Почему выбран**

Облачные серверы Selectel поддерживают подключение к VPC через внутренние интерфейсы, что обеспечивает приватное взаимодействие с базой данных и S3‑хранилищем без трафика в интернете.

**Подтверждение в документации**

Документация Selectel: «К каждому серверу можно подключить приватную сеть через интерфейс vNIC» — docs.selectel.ru/cloud/servers

---

#### Managed Databases

**Продукт:** Управляемые базы данных (PostgreSQL)  
**Роль:** база данных

Управляемая PostgreSQL‑база данных с автоматическими бэкапами, мониторингом и репликацией. Администрирование выполняет Selectel.

**Почему выбран**

Инстанс Managed DB разворачивается в той же VPC‑сети, что и сервер. Подключение по приватному IP исключает утечку данных через публичный интернет.

**Подтверждение в документации**

Документация Selectel: «Инстанс базы данных можно подключить к существующей VPC‑сети для приватного доступа» — docs.selectel.ru/dbaas

---

#### Объектное хранилище

**Продукт:** S3‑совместимое объектное хранилище  
**Роль:** S3‑хранилище

S3‑совместимое хранилище для файлов, медиа, бэкапов и статики. Поддерживает AWS SDK, boto3, s3cmd и другие S3‑совместимые клиенты.

**Почему выбран**

Selectel Object Storage работает с приватными бакетами, доступ к которым ограничивается по ключам доступа. Сервер взаимодействует с хранилищем по API.

**Подтверждение в документации**

Документация Selectel: «Объектное хранилище совместимо с Amazon S3 API и доступно из любой сети при наличии ключей доступа» — docs.selectel.ru/storage

## Задание 4. В чём разница между микросервисами и монолитом


## 🏛️ Монолитная архитектура

Представьте большой торговый центр, где всё — магазины, склад, кассы, охрана — находится под одной крышей и управляется единым руководством.

### Схема монолита

### Преимущества монолита

- Просто начать: один проект, один деплой.  
- Легко тестировать локально.  
- Меньше накладных расходов на коммуникацию.  
- Единая кодовая база — проще навигация.

### Недостатки монолита

- Сложно масштабировать отдельные части.  
- Один баг может «положить» всё приложение.  
- При росте превращается в «спагетти-код».  
- Деплой становится медленным и тяжёлым.

### Аналогия

Монолит — это пиццерия, где один повар делает всё: тесто, соус, начинку и доставку.  
Удобно, пока заказов мало. Но при 1000 заказов в день один человек не справится.

---

## 🔧 Микросервисная архитектура

Представьте торговый центр, где каждый магазин — отдельный бизнес со своей командой, складом и кассой. Они взаимодействуют, но живут независимо.

### Схема микросервисов

### Преимущества микросервисов

- Масштабирование каждого сервиса независимо.  
- Сбой одного сервиса не ломает всё приложение.  
- Разные команды работают автономно.  
- Можно использовать разные технологии под разные задачи.

### Недостатки микросервисов

- Сложнее инфраструктура и поддержка.  
- Появляются задачи распределённых систем.  
- Сетевые задержки между сервисами.  
- Сложнее тестировать весь сценарий целиком.

### Аналогия

Микросервисы — это сеть пиццерий:  
одна команда делает тесто, другая — соус, третья — доставляет.  
Если курьер заболел — пицца всё равно готовится.

## Рекомендации по выбору

- **Выбирайте монолит**, если продукт на ранней стадии, команда маленькая, а скорость разработки важнее гибкости.  
- **Выбирайте микросервисы**, если система растёт, команды множатся, а отдельные части требуют независимого масштабирования.

## Задание 6. Вводный раздел для инструкции «Управлять ключами доступа»

Ниже приведён вводный раздел, который располагается перед пошаговой инструкцией и объясняет пользователю контекст: что такое ключи доступа, зачем они нужны и как работают.

---

## Управлять ключами доступа

### Ключи доступа

Ключи доступа — это пара учётных данных, используемая для аутентификации запросов к API Selectel и S3‑совместимому объектному хранилищу.  
Каждая пара состоит из двух частей:

- **Access Key ID** — идентификатор ключа  
- **Secret Access Key** — секретный ключ для подписи запросов

Ключи позволяют приложениям, скриптам и сторонним инструментам подключаться к сервисам Selectel без использования логина и пароля от личного кабинета.

---

### Зачем нужны ключи доступа

Использовать пароль от аккаунта в коде или конфигурации небезопасно: он даёт полный доступ ко всем ресурсам.  
Ключи доступа решают эту проблему:

- их можно ограничить по правам;  
- привязать к конкретному проекту или бакету;  
- отозвать в любой момент без смены пароля аккаунта.

Такой подход снижает риски и делает интеграции безопаснее.

---

### Как работают ключи доступа

Когда приложение обращается к API, оно передаёт **Access Key ID** и подписывает запрос с помощью **Secret Access Key**.  
Selectel проверяет подпись и, если она корректна, выполняет запрос.

Важно: **Secret Access Key не передаётся по сети** — он используется только для формирования криптографической подписи на стороне клиента.

> ℹ️ **Secret Access Key отображается только один раз — в момент создания.**  
> Сохраните его в надёжном месте. После закрытия страницы восстановить ключ невозможно — потребуется создать новый.

---

### Рекомендации по безопасной работе с ключами

- Не храните ключи в исходном коде и системах контроля версий (Git).  
  Используйте переменные окружения или менеджеры секретов.
- Создавайте отдельный ключ для каждого приложения или окружения (prod/staging/dev).
- Выдавайте ключу минимально необходимые права — принцип наименьших привилегий.
- Регулярно ротируйте ключи: удаляйте старые и создавайте новые.
- Если ключ скомпрометирован — немедленно отзовите его в личном кабинете.

### Структура вводного раздела

1. **Определение** — отвечает на вопрос «что это?»

### Принципы написания вводного раздела

- Логичная структура: отвечает на вопросы «что», «зачем», «как».  
- Каждый абзац — одна мысль, без лишних слов.  
- Фокус на пользователе: зачем ему это и какие риски существуют.  
- Важные предупреждения вынесены в отдельные блоки.
