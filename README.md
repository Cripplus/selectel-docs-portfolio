# Тестовое задание — Технический писатель

## 1. Варианты заголовков статьи

- «Как мы следим за птицами: Android, компьютерное зрение и 10 000 км данных о миграции»

**Почему работает:**

Хабр любит статьи в формате «как мы сделали». Заголовок сразу называет технологии (Android, CV) и обещает конкретику — цифру 10 000 км. Это цепляет и разработчиков, и тех, кто интересуется применением технологий.
- «Программно-аппаратный комплекс для трекинга птиц: архитектура системы от камеры до облачного хранилища»

**Почему работает:**  

Технически точный заголовок, ориентированный на читателей, которые ищут архитектурные решения.  
Описывает полный путь данных — «от камеры до облака».  
Хорошо ранжируется по запросам про IoT и встраиваемые системы.
- «Орнитология на Android: как мобильное устройство и нейросеть помогают учёным изучать миграцию птиц»

**Почему работает:**  

Неожиданное сочетание «орнитология + Android» создаёт интригу.  
Заголовок подчёркивает прикладное применение ML и привлекает широкую аудиторию, включая тех, кто интересуется нестандартными ML‑кейсами.

## 2. Подход к доработке текста по требованиям заказчика

Для приведения текста к техническому формату выполняются следующие действия:

- удаление субъективных и эмоциональных формулировок;
- уточнение технических деталей: архитектуры, используемого оборудования, протоколов и алгоритмов;
- согласование фактической информации с разработчиками;
- унификация терминологии;
- корректировка структуры для обеспечения логичной последовательности;
- проверка соответствия уровня изложения целевой аудитории.

## 3. Инфраструктурная связка Selectel

### Используемые продукты

- **VPC (Virtual Private Cloud)** — единое сетевое пространство для размещения ресурсов.
- **Cloud Compute** — виртуальные серверы для приложения и базы данных.
- **S3‑совместимое объектное хранилище** — хранение файлов, логов и резервных копий.

### Обоснование совместимости

- Все ресурсы могут быть развёрнуты внутри одной VPC.
- Cloud Compute подходит для размещения серверных компонентов и СУБД.
- Объектное хранилище поддерживает Amazon S3 API.
- Внутренний трафик между продуктами не тарифицируется.

## 5. Разница между микросервисами и монолитом

### Монолит

Цельное приложение, включающее весь функционал и использующее единую базу данных. Изменения в одном компоненте могут затрагивать всю систему.

### Микросервисы

Набор независимых сервисов, каждый из которых отвечает за отдельный функциональный блок. Сервисы разворачиваются, обновляются и масштабируются автономно.

## 6. Вводный раздел к инструкции «Управлять ключами доступа»

Ключи доступа — это пара идентификаторов (Access Key и Secret Key), используемых для аутентификации при работе с API и S3‑совместимым хранилищем.  
Они применяются для автоматизации операций загрузки и выгрузки данных, интеграции внешних сервисов и выполнения фоновых процессов.

Ключи наследуют права пользователя или назначенной роли. Их необходимо хранить в защищённом месте. При необходимости ключи могут быть отозваны и созданы повторно.
